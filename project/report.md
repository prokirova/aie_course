## 2. Постановка задачи и контекст


**Предметная область** - клиентская аналитика подписочного сервиса. Потенциальный пользователь - CRM-система или менеджер поддержки, которому нужно быстро понять, есть ли в обращении клиента намерение уйти.

**ML-задача** - бинарная классификация churn intent:

- вход: текст обращения `message` и метаданные клиента;
- выход: `churn_intent = 1`, если обращение похоже на намерение уйти, иначе `0`;
- API возвращает класс, вероятность и уровень риска `low` / `medium` / `high`.

**Основные метрики:** ROC-AUC, F1, precision, recall и accuracy. ROC-AUC показывает качество ранжирования клиентов по риску, F1 важен для баланса precision/recall.

## 3. Данные

Опишите, какие данные использует проект:

1. **Источник данных:**

## 4. Модели и подходы

**Финальный подход:**

1. `Qwen/Qwen2.5-0.5B-Instruct`, сохранённый локально в `models/qwen2.5-0.5b-instruct`, превращает `message` в embedding.
2. Числовые признаки проходят через `StandardScaler`.
3. Категориальные признаки проходят через `OneHotEncoder(handle_unknown="ignore")`.
4. Embedding текста и обработанные метаданные склеиваются в один вектор.
5. Поверх него обучается sklearn-классификатор.

Сравнивались:

- `DummyClassifier` как baseline;
- `LogisticRegression` поверх Qwen embeddings;
- `RandomForestClassifier` поверх Qwen embeddings.

## 5. Экспериментальный протокол и результаты

Здесь важно показать, что выбор финальной модели был осмысленным.

1. **Экспериментальный протокол:**
   - Полный датасет содержит 100 000 строк. Для ускорения воспроизводимого обучения embeddings считаются на sample `3000`, заданном в `configs/config.json`. Разбиение: stratified train/test, `test_size=0.2`, `random_state=42`.

2. **Сравнение моделей по метрикам:**

  | Модель | Accuracy | Precision | Recall | F1 | ROC-AUC | Комментарий |
|---|---:|---:|---:|---:|---:|---|
| `dummy_most_frequent` | 0.585 | 0.000 | 0.000 | 0.000 | 0.500 | формальный baseline |
| `transformer_embeddings_logistic_regression` | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 | финальная модель |
| `transformer_embeddings_random_forest` | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 | качество такое же, модель тяжелее |

3. **Выбор финальной модели:**
   - Финальная модель - `transformer_embeddings_logistic_regression`. Она выбрана, потому что на синтетической задаче даёт максимальные метрики, при этом проще, быстрее и легче для API, чем RandomForest. Идеальные метрики объясняются синтетической природой данных: формулировки churn intent в генераторе достаточно явно отделены от позитивных/нейтральных обращений.

## 6. Архитектура решения и сервис

Опишите, как из модели получился работающий сервис:

1. **Архитектура пайплайна:**
   - `generate text data -> Qwen embeddings -> metadata preprocessing -> train classifiers -> save artifacts -> FastAPI /predict`

Основные файлы:

- `src/data/generate.py` - генерация 100k текстовых обращений;
- `models/qwen2.5-0.5b-instruct` - локальная папка предобученного Qwen;
- `src/models/transformer_embedder.py` - загрузка Qwen и расчёт embeddings;
- `src/train.py` - обучение и сохранение `artifacts/churn_model.joblib`;
- `src/models/inference.py` - загрузка артефакта и инференс;
- `src/service/app.py` - API.

2. **API и endpoints:**
   - Endpoints:

- `GET /health` - статус сервиса, наличие модели и путь к transformer model;
- `POST /predict` - предсказание churn intent;
- `GET /metrics` - счётчики запросов, ошибок и средняя задержка;
- `GET /model-info` - метрики последнего обучения из `artifacts/metrics.json`.


3. **Технологический стек:**
   - Python 3.12, PyTorch + Transformers (Qwen), scikit-learn, FastAPI + Uvicorn, Docker, pandas/numpy.

## 8. Ограничения и дальнейшая работа

Главное ограничение - синтетическая природа данных. Метрики показывают, что pipeline работает, но не доказывают качество на реальных обращениях. Для реального применения нужно взять открытый или обезличенный support/churn dataset, добавить более шумную разметку и проверить устойчивость модели.

Дальнейшие шаги:

- заменить синтетику на реальный датасет;
- добавить MLflow для трекинга экспериментов;
- добавить batch endpoint;
- добавить мониторинг дрейфа текстов и метаданных;
- настроить CI для тестов и сборки Docker-образа.
