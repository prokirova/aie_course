# Итоговый проект по курсу «Инженерия Искусственного Интеллекта»

В этой папке находится итоговый мини-проект по курсу.  
Проект должен демонстрировать применение методов и инструментов инженерии ИИ: работу с данными, модели, пайплайны, сервис, эксперименты и (по возможности) воспроизводимость.

Сервис принимает текст обращения клиента и несколько метаданных, строит embedding предобученным Qwen, затем классифицирует churn intent лёгкой ML-моделью поверх эмбеддингов. Есть генерация данных, EDA, сравнение моделей, FastAPI, Dockerfile, `/health`, `/metrics`, конфиги и тесты.


---

## 2. Структура проекта

Проект организован в следующей структуре:

- `requirements.txt` – зависимости проекта (библиотеки Python, необходимые для запуска).
- `report.md` – отчёт по проекту (постановка задачи, данные, эксперименты, результаты).
- `self-checklist.md` – чеклист самопроверки проекта перед сдачей.
- `notebooks/` – экспериментальные ноутбуки:
  - EDA, прототипы моделей, отдельные эксперименты.
- `src/` – основной код проекта:
  - модули для работы с данными;
  - обучение моделей;
  - запуск сервиса/скриптов.
- `data/` – демонстрационные/учебные данные:
  - **только открытые, синтетические или обезличенные данные;**
  - при необходимости – небольшие выборки для быстрого запуска.
- `configs/` – конфигурационные файлы:
  - `.yaml`, `.json`, `.env.example` и т.п.
- `tests/` – тесты (юнит-тесты, простые проверки).
- `artifacts/` – сохранённые модели, отчёты, результаты экспериментов.

Если структура проекта отличается от базовой, опишите это здесь.

## 3. Требования и установка

### 3.1. Требования

- Python `>= 3.12` 
- Важно: в конфиге стоит `"device": "cuda"`. Если CUDA недоступна, код падает с явной ошибкой, а не уходит молча на CPU.


### 3.2. Установка окружения

Примерный сценарий (можно адаптировать под ваш проект):

```bash
cd project
python -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

## 4. Как запустить проект

Опишите, как именно воспроизвести основные сценарии использования проекта.

Примеры (заполните под свой случай):

### 4.1. Запуск обучения модели

```bash
cd project
source .venv/bin/activate
python -m src.train
```

### 4.2. Запуск сервиса (API/веб-интерфейс)

```bash
cd project
source .venv/bin/activate
python -m src.service
```

Сервис поднимается на `http://0.0.0.0:8000`.

Endpoints:

- `GET /health`
- `POST /predict`
- `GET /metrics`
- `GET /model-info`

Пример:

```bash
curl -X POST http://127.0.0.1:8000/predict \
  -H "Content-Type: application/json" \
  -d '{
    "message": "хочу закрыть аккаунт, сервис стал слишком дорогим",
    "urgency": 5,
    "months_active": 7,
    "support_tickets": 4,
    "discount_requested": 1,
    "channel": "chat",
    "segment": "individual"
  }'
```
Docker

Сборка:

```bash
cd project
docker build -t churn-risk-api .
```

Запуск с GPU:

```bash
docker run --gpus all -p 8000:8000 churn-risk-api
```

Контейнер разворачивает FastAPI на порту `8000`. Обученный `artifacts/churn_model.joblib` и папка `models/qwen2.5-0.5b-instruct` попадают внутрь образа через `COPY . .`, поэтому внешний HF-кэш не нужен.
